- 머지하면 즉시 라이브입니다. PR만 만들고 main에 직접 올리지 않습니다.

## 왜

지금 사이트는 4개 언어가 똑같은 "강남 병원 의료통역" 한 장입니다. 사장님 결정으로 언어마다 손님이 달라집니다.

| 언어 | 손님 | 대표 문구 | 주 버튼 |
|---|---|---|---|
| 한국어 `/ko/` | 중국 손님을 받는 업체(병원·뷰티샵·기업) = B2B | 중국 손님이 오는 날, 목적을 돕는 통역사를 불러 주세요. | 문자 |
| 번체 `/zh-tw/` | 대만·홍콩 개인 손님 = B2C | 在韓國，不因為語言而吃虧。 | 인스타그램(계정 값이 들어오기 전에는 위챗) |
| 간체 `/` | 해외 중국어권 개인 손님 = B2C | 在韩国，不因为语言吃亏。 | 위챗 |
| 영어 `/en/` | 번체와 같은 구성 = B2C | In Korea, never lose out because of language. | 메일 |

이번 1차는 **지금 있는 4개 주소 안에서 홈만** 바꿉니다. 서비스별 하위 페이지, 블로그, 새 도메인 연결은 다음 요청서에서 따로 합니다.

## 할 일

### 1. 빌드 구조

1. 템플릿을 둘로 나눕니다. `tools/template-b2b.html`(ko), `tools/template-b2c.html`(zh-CN, zh-TW, en). head·헤더·바닥·위챗 모달처럼 같은 부분은 공통 조각으로 빼도 됩니다. 기존 `tools/template.html`은 지웁니다.
2. `tools/build.js`에 설정 묶음을 하나 둡니다. 나중에 한 줄만 바꾸면 되게 하기 위해서입니다.
   - `ORIGIN`: 지금 값 `https://coorocket.github.io/jstars` 유지 (새 도메인 연결 때 이 값만 바꿉니다)
   - `LASTMOD`: 이 PR을 만드는 날짜 `YYYY-MM-DD` 고정 문자열 (현재 시각을 읽어 넣지 않습니다)
   - `GA_ID`: 빈 문자열. 비어 있으면 gtag 스크립트를 불러오지 않습니다
   - `INSTAGRAM_URL`: 빈 문자열. 비어 있으면 인스타그램 버튼을 만들지 않고 위챗이 주 버튼이 됩니다
3. HTML·CSS·JS 안에 `/jstars/`로 시작하는 절대 경로가 없게 합니다(canonical·og·사이트맵처럼 `ORIGIN`에서 만들어지는 값만 예외). 새 도메인에서는 사이트가 `/`에 놓이기 때문입니다.
4. zh-TW 사전은 이제 손으로 쓴 값입니다. `tools/make-zh-tw.py`로 덮어쓰지 않습니다. `tools/README.md`에 이 점과 새 템플릿 구조를 적습니다.
5. 사전 키 이름은 기존 규칙에 맞춰 정하되, 문구는 아래 값을 그대로 씁니다. 아래에 없는 기존 문구(예: a11y, 위챗 모달 제목, 토스트)는 그대로 둡니다.
6. `styles.css?v=`와 `app.js?v=` 값을 새 날짜로 올립니다.

그 밖의 head 값

- canonical, robots.txt: 바꾸지 않습니다.
- hreflang: 기존 6줄(zh-CN, zh-TW, zh-HK, ko, en, x-default)은 그대로 두고 **2줄을 더합니다.** `zh-Hans` → `/`, `zh-Hant` → `/zh-tw/`. head와 sitemap 양쪽에 같게 넣습니다.
- `<html lang>` 값(zh-CN, zh-TW, ko, en)은 바꾸지 않습니다.
- og 이미지 파일은 그대로 씁니다.
- JSON-LD(ProfessionalService·LocalBusiness): `description`은 새 description, `areaServed` `["Seoul", "South Korea"]`, `knowsLanguage` `["ko", "zh-Hans", "zh-Hant"]`, `priceRange` `"₩30,000~ / hour"`, `serviceType`은 `["Chinese–Korean consecutive interpretation", "Medical interpretation", "Beauty and personal colour interpretation", "Business meeting interpretation", "VIP escort interpretation", "Document translation"]`. `email`은 지금 값 유지. 주소·전화·설립연도는 넣지 않습니다.
- JSON-LD FAQPage를 페이지마다 하나 더합니다. 화면의 FAQ 문답과 글자가 같아야 합니다.

### 4. 한국어 홈 `/ko/` (B2B) 구역과 문구

구역 순서: 헤더 → 첫 화면 → 근거 줄 → 위험 → 업종 카드 → 비교표 → 세 가지 원칙 → 부르는 법 → 요금 → 통역사 → 상황 → 다음 단계(시엠디랩) → FAQ → 문의 → 바닥 → 모바일 하단 바

**헤더 메뉴:** 업종별 통역 / 부르는 법 / 요금 / 통역사 / FAQ (모두 같은 페이지 안 이동). 오른쪽 버튼은 지금처럼 전화·문자(번호를 JS에서 조립하는 지금 방식 유지).

**첫 화면**

- H1(윗줄): 위 3번 표
- 큰 문구: `중국 손님이 오는 날,<br>목적을 돕는 통역사를<br>불러 주세요.`
- 공감: `번역 앱으로 상담하다가 손님이 그냥 돌아간 적, 있으시죠?`
- 3줄(지금 "진료 전·진료 중·끝나기 전" 자리):
  - `필요한 날, 필요한 시간만` / `중국어 직원을 따로 뽑지 않아도 됩니다.`
  - `자료를 미리 읽고 갑니다` / `가격표·동의서를 먼저 받아 현장에서 말이 막히지 않습니다.`
  - `쓰리 필터링, 세 번 확인합니다` / `상담 때, 진행 전, 결제 전. 합의한 내용 그대로 결제됩니다.`
- 주 버튼: `무료 사전 상담 (문자)` (`data-contact="sms"`) / 보조 버튼: `전화 상담` (`data-contact="tel"`)

- 작은 링크: `위챗 상담` (모달). 체크리스트 내려받기 링크는 첫 화면에서 빼고 문의 구역에만 둡니다.
- 점 2개: `없는 사실을 지어내지 않습니다` / `상담 내용 비밀 유지`
- 사진과 사진 위 딱지: 지금 그대로

### 6. 4개 언어 공통 정리

1. 아래 뜻의 문구는 어느 언어에도 남기지 않습니다: "먼저 문의하고 나중에 결정해도 됩니다", "바로 결정하지 않아도 됩니다", "아직 정하지 않으셨어도 괜찮습니다". 남아 있으면 그 자리에 무료 사전 상담 문장을 씁니다.
2. "20+년", "20년" 표기는 화면에서 뺍니다. 경력은 "2007년부터"로만 씁니다. 바닥의 `SEOUL · GANGNAM · KOREA`는 `SEOUL · KOREA`로 바꿉니다. 사진 alt와 그대로 두는 기존 문답 안의 "강남"은 손대지 않습니다.
3. 지금의 "두 가지 요구(FOR PATIENTS / FOR CLINICS)" 구역은 양쪽 템플릿에서 뺍니다. 사진 2장은 위에 적은 통역사 구역에서 다시 씁니다.
4. 모든 연락 버튼과 내려받기 링크에 `data-track="위치"`를 붙입니다. 위치 이름: `header_cta`, `hero_cta`, `hero_sub`, `process_cta`, `faq_cta`, `contact_cta`, `sticky_mobile`, `next_cmdlab`, `checklist_download`. `app.js`에 듣는 코드를 하나 두고, `window.gtag`가 있을 때만 `cta_click` 이벤트(`cta_position`, `cta_channel`: tel·sms·wechat·instagram·email·download, `page_lang`)를 보냅니다. `GA_ID`가 비어 있는 동안에는 아무것도 불러오지 않습니다.

### 7. 속도

1. 글꼴: 페이지마다 자기 언어 글꼴 1종만 불러옵니다. ko는 Noto Sans KR, zh-CN은 Noto Sans SC, zh-TW는 Noto Sans TC. en은 웹폰트 링크를 넣지 않고 시스템 글꼴로 표시합니다. 언어 전환 단추 안의 다른 언어 글자는 시스템 글꼴로 보여도 됩니다. 새 글꼴·새 외부 스크립트는 넣지 않습니다.
2. 위챗 QR: 원본 `assets/jstarstudio-wechat-qr.png`는 그대로 두고 "QR 이미지 저장" 버튼에만 씁니다. 화면 표시용으로 가로 640px 사본 `assets/wechat-qr-640.png`(100KB 이하)를 만들어 문의 구역과 모달에 `loading="lazy"`로 씁니다. 사본이 읽히는지 QR 해독으로 확인하고, 확인하지 못했으면 결과에 "미확인"이라고 적습니다.
3. 그 밖의 사진(히어로, 사진 6장, og 4종, 파비콘)은 다시 압축하거나 다시 만들지 않습니다.

### 8. 사이트맵과 llms.txt

1. `sitemap.xml`: 주소 4개는 그대로. 각 주소에 `<lastmod>`(설정의 `LASTMOD`)를 넣고, hreflang 2줄(zh-Hans, zh-Hant)을 더합니다.
2. 저장소 루트에 `llms.txt`를 새로 만듭니다(주소는 `ORIGIN/llms.txt`). 내용은 아래 그대로, `{ORIGIN}`만 빌드 값으로 바꿉니다.

## 완료 기준 (Claude Code 자체검증)

1. `node tools/build.js`가 오류 없이 4개 페이지, `sitemap.xml`, `llms.txt`를 만들고, 다시 돌려도 결과가 같다(생성물과 템플릿이 어긋나지 않음).
2. 4개 페이지 각각: `<html lang>` 그대로, canonical 그대로, hreflang 8줄(기존 6 + 추가 2), og:image 언어 일치, title·description·H1이 3번 표와 글자 단위로 같다. H1은 페이지당 1개.
3. `sitemap.xml`의 `<loc>` 4개가 이전과 같고 lastmod가 `LASTMOD` 값이다. `robots.txt`는 diff 없음.
4. 4개 페이지 전체에서 다음 낱말 검색 결과 0건: `Jstar Studio`(JSON-LD alternateName과 위챗 QR 파일 이름 제외), `20+`, `LINE`, `WhatsApp`, 그리고 6-1의 세 문구 뜻에 해당하는 문장.
5. JSON-LD 2개(업체, FAQPage)가 JSON으로 읽히고, FAQPage 문답이 화면 FAQ와 같다.
6. ko에만 전화·문자 버튼과 시엠디랩 구역이 있고, 그 밖의 언어에는 없다. zh-TW는 `INSTAGRAM_URL`이 빈 값이라 위챗이 주 버튼이다.
7. 모든 연락 버튼에 `data-track`이 있다. gtag 스크립트는 어디에도 없다.
8. 페이지마다 웹폰트 링크가 1종 이하다. en은 0종.
9. 모바일 폭 375px에서 4개 페이지 모두 가로 넘침이 없다(가능하면 화면 캡처 첨부). 비교표는 표 안에서만 밀린다.
10. HTML·CSS·JS에 `/jstars/`로 시작하는 절대 경로가 `ORIGIN`에서 나온 값 말고는 없다.
11. 결과 메모에 변경 파일 목록, 바뀐 title·H1 4쌍, 새 `data-track` 위치 목록, 하지 못한 것을 적고 "머지 즉시 라이브" 경고를 넣는다.
